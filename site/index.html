01 boobies-media

The library

One Go binary, one data directory.

A media server for a handful of people who trust each other. It stores images and video, makes them searchable, and produces share pages that unfurl properly in Discord.

No object storage, no external database, no managed services. State lives in SQLite and a directory of content-addressed files, so a backup is a copy of one folder.

Resumable uploads
Files are split into 12 MiB chunks, so a dropped connection resumes instead of restarting, and a proxy body limit never caps how large a file can be. Ceiling is 8 GiB per file.
Ingest from a link
Paste a URL and the server fetches it: direct downloads, Discord CDN, Twitter/X, YouTube, TikTok, Medal. yt-dlp handles extraction with a gallery-dl fallback for galleries.
SSRF protection
Remote fetches validate the real connection at every redirect hop and refuse private, loopback, link-local, CGNAT and reserved destinations. A redirect cannot walk a fetch into your network.
Content-addressed storage
Blobs are keyed by SHA-256 of the stored bytes, so the same file uploaded twice occupies disk once. Reference counting keeps cleanup honest.
Probes and thumbnails
Dimensions, duration and thumbnails are produced by background workers, so an upload returns as soon as the bytes land. Optional lossless WebP conversion.
Folders, tags, search
A shared folder tree with bulk moves, free tags, keyset-paginated browsing, and a random-item endpoint for when you just want something.
Share pages
Anonymous per-item pages built for Discord's crawler, with separate routes for stills, animation and video so an embed plays instead of linking out.
Two ways to authenticate
Secure session cookies for people, Authorization: Bearer for machines. Passwords are argon2id; sessions and API keys are stored only as hashes.
Operations
Admin views for users, jobs, settings, dependency health and trash, plus nightly SQLite snapshots with seven-copy retention.
A small front end
Server-rendered HTML with TypeScript islands under a 50 KB bundle budget. No framework runtime ships to the browser.

02 booby-bot

The collector

React to a message. It's filed.

A Discord bot that saves attachments and links into the library. It never downloads a byte: it hands the media server a URL and lets the server fetch it, which is why saving a YouTube link works the same as saving a screenshot.

That decision keeps the container at 13 MB with no ffmpeg, no yt-dlp, and no volume beyond a small SQLite file.

Four ways to save
React with an emoji, post in a watched channel, run /upload, or pick Save to media from a message's context menu. The first two stay silent; the other two reply only to you.
Old messages work
Discord attachment links carry a rotating signature and expire. The bot re-fetches the message when you react, so a year-old post yields a link that is valid right now.
Never saved twice
Identity is the attachment's snowflake, discord:attachment:<id>, not its URL. Re-reacting, or pasting the CDN link for a file someone already saved, is recognised as the same item.
Two people, one entry
The save is claimed in SQLite before any network call, so simultaneous reactions race on a unique constraint rather than on the media server. Exactly one wins.
Restart-safe
Unfinished work is recorded before it is submitted. On restart the bot resumes polling, and an ambiguous claim is reported rather than resubmitted, because a duplicate is worse than a retry you can do yourself.
Files itself
Channels map to folders, forum posts inherit their parent's mapping, and every item is tagged with who posted it, which server and which channel.
Bounded by design
Per-user and per-server token buckets, a bounded queue, and a cap on URLs per message. One person cannot spend everyone's budget.

03 How a save happens

01

Trigger

Someone reacts, or posts in a watched channel. The handler records identifiers and returns immediately.

02

Claim

A row is written to the bot's ledger before anything leaves the process. This is what makes a second trigger a no-op.

03

Fetch

The library downloads the URL under its own SSRF rules, deduplicates the bytes, probes metadata and builds a thumbnail.

04

File

The bot sets the folder, applies tags, and marks the message with a reaction. Nothing is posted to the channel.

04 Run it yourself

boobies-media the library 
# build the browser assets and the server
bun install && make build

# create the first administrator, prints an API key once
./bin/server user add admin --admin

# serve on loopback with a local data directory
./bin/server -addr 127.0.0.1:8080 -data ./data \
  -base-url http://localhost:8080 -insecure-cookies
booby-bot the collector 
# Message Content Intent must be on in the Developer Portal
docker build -t booby-bot .

docker run -d --name booby-bot \
  -e BB_DISCORD_TOKEN -e BB_GUILDS \
  -e BB_MEDIA_BASE_URL -e BB_MEDIA_API_KEY \
  -v booby-bot-data:/data booby-bot

Both ship a Dockerfile. The library wants a persistent volume and a hostname; the bot wants a volume and nothing else, since it opens no listening port. Production notes, Cloudflare Tunnel topology and the full environment reference live in the repositories.
